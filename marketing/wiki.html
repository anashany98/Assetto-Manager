Documentación Técnica

Bienvenido a la Wiki Oficial de Assetto Manager. Esta guía está diseñada para instaladores y operadores de SimCenters, cubriendo desde el despliegue inicial hasta la operativa diaria avanzada.

Servidor de Gestión

Instalado en el PC de Recepción. Aloja la base de datos centralizada, la interfaz de administración y el motor de sincronización de contenido.

Agente de Estación

Un servicio ligero instalado en cada cockpit. Ejecuta el juego, cambia la configuración de hardware al vuelo e informa del estado del PC.

01 Requisitos Mínimos

Servidor (Master)

  • SO: Windows 10/11 o Ubuntu 22.04+ LTS.
  • Software: Node.js 18+, Python 3.10+.
  • DB: PostgreSQL (Soporte nativo para Supabase).
  • Red: Conexión Gigabit Ethernet recomendada.

Simuladores (Nodes)

  • SO: Windows 10 Pro (imprescindible para Modo Kiosko).
  • Juego: Assetto Corsa (con Steam abierto).
  • Software: Python 3.10+ (para el Agente).
  • Hardware: Volante Direct Drive / Logitech / Fanatec.

02 Instalación del Servidor Master

El PC de recepción gestiona la lógica del negocio.

1. Clonar e Instalar

git clone https://github.com/tu-usuario/ac-manager.git
cd ac-manager
install_dependencies.bat

2. Configurar Variables de Entorno (.env)

Crea un archivo backend/.env con tus credenciales:

DATABASE_URL=postgresql://user:pass@localhost:5432/ac_manager
SECRET_KEY=clave_ultra_segura
ENABLE_TELEMETRY=true

3. Primer Arranque

Utiliza el script de inicio unificado para mayor comodidad:

START_SYSTEM.bat

Acceso Web: http://localhost:3010

LAN: para acceder desde otras máquinas, usa start_server.bat (o ejecuta Frontend con --host y Backend con --host 0.0.0.0). Ver sección LAN.

03 Instalación de Agentes (Simuladores)

El Agente es el puente entre el servidor y el juego.

1. Distribución de Archivos

Copia la carpeta /agent a una ruta limpia en el PC simulador (ej: C:\AssettoManager\agent).

2. Configuración de Red (config.json)

En cada simulador, edita config.json para apuntar al servidor:

{
  "server_url": "http://192.168.1.50:8000",
  "station_name": "Simulador 01",
  "ac_path": "C:\\Program Files (x86)\\Steam\\steamapps\\common\\assettocorsa"
}

Ojo: La IP debe ser la del PC Master en tu red LAN.

3. Activación

python main.py

Tip: Crea un acceso directo en 'Inicio' de Windows para que el agente arranque solo.

04 Licencia y Módulos (Activación)

Assetto Manager valida la licencia de forma offline (JWT RS256 firmado) y habilita funciones por módulos. En ENVIRONMENT=production la API bloquea endpoints no licenciados con 403.

Activación

  • 1. Panel: abre Ajustes y pega el token de licencia.
  • 2. API (opcional): POST /license (requiere admin) para guardar la licencia.
  • 3. Verifica: GET /license devuelve cliente, expiración y módulos.

Requiere clave pública en certs/public_key.pem (o LICENSE_PUBLIC_KEY / LICENSE_PUBLIC_KEY_PATH).

Forzar validación en desarrollo
ENFORCE_LICENSE=true

Además de la licencia global, el backend soporta permisos por usuario para limitar acceso a módulos incluso si están licenciados.

Mostrar solo módulos autorizados

Recomendación: el frontend puede consumir GET /license y filtrar el menú en base a modules (y a los permisos del usuario autenticado) para que solo aparezca lo habilitado.

05 LAN (Red y Puertos)

En un SimCenter, el 90% de los problemas son red: IP incorrecta, puertos bloqueados o servicios escuchando solo en 127.0.0.1. Esta sección te deja el checklist mínimo.

Puertos estándar

  • 8000/TCP Backend API + WebSocket (agentes y telemetría).
  • 3010/TCP Panel web (Frontend).
  • 8800/TCP License Admin (opcional, solo si lo despliegas).

Arranque accesible desde LAN

Para que otros PCs accedan, el Backend debe escuchar en 0.0.0.0 y el Frontend debe exponerse con --host. 

start_server.bat

Nota: start_system.bat es cómodo para local, pero por defecto no expone a la LAN (solo localhost).

Firewall (Windows)

Reglas inbound típicas para el PC Master:

New-NetFirewallRule -DisplayName "Assetto Manager Backend" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8000
New-NetFirewallRule -DisplayName "Assetto Manager Panel" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 3010

WS y multi-worker (nota realista)

Para telemetría/TV en tiempo real, una sola instancia suele ser lo más estable. Si ejecutas múltiples workers/procesos, necesitas sticky sessions y/o un broker (por ejemplo Redis) para distribuir eventos, porque las conexiones WebSocket activas viven en memoria del proceso.

Observabilidad (logs y métricas)

  • Salud: GET /health
  • Métricas snapshot: GET /system/metrics (admin)
  • Logs recientes: GET /system/logs (admin)

Recomendación: en producción centraliza logs (Loki/ELK) y monitoriza latencia, caídas y desconexiones WS de estaciones.

Backups y actualizaciones

En producción usa PostgreSQL y programa backups. En pruebas con SQLite, el backup es copiar el archivo .db. 

# PostgreSQL (ejemplo)
pg_dump -Fc -f ac_manager.backup.dump "postgresql://user:pass@host:5432/ac_manager"

Actualizaciones de Agente: sube un ZIP con POST /system/update y los agentes consultan GET /system/version.

06 El Dashboard (Panel de Control)

Primer acceso (crear admin)

Si al iniciar sesión recibes Invalid credentials y es una instalación nueva, primero debes crear el usuario admin (solo funciona si aún no hay usuarios). 

# PowerShell
$body = @{ username = "admin"; password = "cambia-esto" } | ConvertTo-Json
Invoke-RestMethod -Method POST "http://localhost:8000/users/setup" -ContentType "application/json" -Body $body

En producción configura SETUP_TOKEN y envía el header X-Setup-Token.

El núcleo de Assetto Manager. Una vista de pájaro de todo tu negocio.

Telemetría de Hardware

Cada tarjeta muestra el % de CPU, RAM y GPU del simulador. Si un valor se pone rojo, el sistema emitirá una alerta visual.

Detección de Periféricos

Identifica automáticamente si el volante y los pedales están correctamente conectados por USB antes de que el cliente se siente.

07 Gestión de Sesiones

Flujo de Lanzamiento:

  1. Selección: Haz clic en un simulador libre. El sistema te pedirá el nombre del piloto (para el Leaderboard).
  2. Configuración: Elige coche, pista y tiempo. Activa el interruptor VR si el cliente usará gafas.
  3. Arranque: Al pulsar "Iniciar", el Agente cierra procesos innecesarios, ajusta los `.ini` del juego y lanza el simulador.

Automatización VR Profesional

Solución de Problemas

¿Simuladores aparecen Offline?

1. Revisa que main.py esté abierto en el PC simulador.

2. IP: Verifica que `config.json` tenga la IP correcta del PC de recepción.

3. Puertos: Asegúrate de que el puerto 8000 (servidor) no esté bloqueado por el cortafuegos.

¿El juego no lanza VR?

1. Selecciona el modo VR en el panel antes de pulsar "Lanzar".

2. Abre SteamVR o el software de Oculus ANTES de iniciar la sesión.

¿No carga contenido nuevo?

1. Asegúrate de que el archivo es un .zip estándar.

2. Revisa el espacio en disco en el PC Servidor.
